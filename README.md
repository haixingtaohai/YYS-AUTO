## 项目简介

YYS-AUTO 是一个用 Python 编写的阴阳师手游自动化工具。它通过 **ADB** 与安卓模拟器通信，用 **OpenCV 模板匹配**识别游戏画面，再以模拟点击 / 滑动的方式完成刷图、组队、爬塔等重复性日常操作。

整套程序为零外部 GUI 依赖的桌面应用：界面用 Python 内置的 Tkinter，识别与通信全部通过 `subprocess` 调用自带 ADB 完成，开箱即用。多标签运行时，困28 队长完成任务或异常中止会自动带停唯一的困28 队员标签，减少看守。

| 指标 | 数值 |
| :--- | :--- |
| 当前版本 | **V2.17.2**（2026-10-30） |
| 场景预设 | **14** 个 |
| 模板图片 | **143** 张 |
| 代码行数 | 约 6500 行 |
| 运行平台 | Windows（Python 3.8+，兼容 3.11） |
| 多设备 | 支持，每个标签页独立线程控制一台模拟器 |

## 功能特性

### 🎯 自动化能力

- **挑战计数器** —— 精确追踪每次挑战次数，支持设置目标上限，达到后自动停止，防止过度消耗体力。
- **司机 / 队员联动** —— 智能组队配对：司机发起邀请后队员自动接受，无需手动协调。
- **多设备并行** —— 选项卡式 UI，每个标签独立控制一台模拟器实例，互不干扰。
- **绘卷模式** —— 依据突破券数量在**结界突破**与**困28单人**之间自动切换，最大化产出效率。
- **自动关闭加成** —— 达到目标次数后强制停止并重启游戏进程，彻底清除已生效的经验 / 金币加成。
- **被顶号自动处理** —— 全局最高优先级检测；被顶号后自动关闭游戏、等待可配置秒数（默认 30 秒）、重启并进入游戏。
- **多庭院识别** —— 支持 5 种庭院探索页（茨心乐园、织梦莲庭、枫色秋庭、默认庭、默认焕新庭）自动进入场景。
- **随机暂停状态** —— 模拟真人无法实时盯屏的行为，按随机区间暂停当前标签页的识别与点击，白名单场景不触发。

### 🖥️ 使用体验

- **配置持久化** —— 设备、场景、阈值、窗口位置等全部写入 `config.json`，重启后自动恢复。
- **阈值独立记忆** —— 每个场景单独记忆识别阈值，切换场景时自动恢复；「重置默认」一键清空。
- **一键应用到所有** —— 当前标签页的运行参数与场景选择可一键同步到全部设备标签。
- **运行时长记录** —— 按场景累计统计运行时长，持久化到 `usage_records.json`，入口在「运行」菜单。
- **完整快捷键** —— 标签管理、启停、批量操作、标签切换全都有键盘映射，输入框聚焦时自动屏蔽。
- **任务结束提示音** —— 任务结束播放 WAV 音效，设置页支持导入、试听与切换，内置 6 款音效。
- **系统级通知** —— 任务完成或异常停止时推送 Windows Toast 通知（`winotify`，未安装则回退 PowerShell 托盘通知）。
- **可控日志** —— ADB 命令、识图结果、GUI 运行日志分别写入 `logs/`，默认关闭，可在菜单栏一键开关。

## 快速开始

**1. 准备模拟器**

安装 MuMu / 雷电等模拟器，在设置中将分辨率调整为 `1280×720`（横屏），并开启 ADB 调试。

**2. 安装依赖**

确保已安装 Python 3.8+，然后运行：

```bash
bat\install.bat
```

**3. 启动程序**

双击根目录的 `运行程序.lnk`，或运行 `bat\run.bat`（启动失败会自动补装依赖并重试）。

**4. 连接设备**

在程序内填写 ADB 的 IP 与端口（默认 `127.0.0.1:16384`），点击「刷新」拉取设备列表并选中目标模拟器。程序会自动校验分辨率是否满足 720p。

**5. 选择场景并运行**

在设备标签页中选择场景预设，设置目标挑战次数、识别阈值、匹配线程数等参数，点击「开始」即可。多设备时可用「全部开始」批量启动，或用「一键应用到所有」同步参数。

**6. 等待完成**

任务完成后会播放提示音并推送系统通知，也可以随时手动停止或调整参数。所有设置自动保存，下次启动无需重新配置。

## 工作原理

程序通过一个闭环完成自动化：

```
┌──────────┐  截图   ┌───────────┐  模板匹配  ┌──────────┐
│  模拟器   │ ─────→ │    ADB    │ ────────→ │  OpenCV  │
│ (游戏画面) │        │  截图命令  │           │ 识别引擎  │
└──────────┘  点击   └───────────┘  匹配结果  └──────────┘
     ↑        ←────      ↑            ←────       │
     │      ADB 点击命令   │                        │
     │                   │    ┌──────────┐          │
     │                   └─── │  场景模块  │ ←────────┘
     │                        │  业务逻辑  │   决策：点哪里
     └────────────────────────┴──────────┘
```

1. **截图** —— `adb exec-out screencap` 拉取原始 RGBA 画面，直接转为灰度图。
2. **识别** —— 以 `TM_CCOEFF_NORMED`（归一化交叉相关）对场景模板做匹配，超过阈值即视为命中，取模板中心作为点击坐标。
3. **决策** —— 场景模块根据识别结果决定下一步动作，返回 `SceneResult` 交给主循环。
4. **执行** —— 通过 `adb shell input tap / swipe` 下发点击或滑动，坐标附加 ±10 像素随机抖动。

**关键技术参数**

| 参数 | 取值 |
| :--- | :--- |
| 匹配算法 | `TM_CCOEFF_NORMED` |
| 预设阈值 | `0.80`（可在界面按场景调整，引擎默认 `0.90`） |
| 点击偏移 | ±10 px 随机抖动 |
| 分辨率 | 720p（启动时校验） |
| 通信方式 | ADB via `subprocess` |
| 线程模型 | 每个标签页一条 Daemon 线程 |

### 技术栈

`Python 3.8+` · `OpenCV (opencv-python)` · `Tkinter` · `ADB` · `NumPy` · `JSON` · `Threading` · `logging` · `winotify` · `Numba JIT`（可选）· `PyTurboJPEG`（可选）

## 性能与加速

`image_accelerator.py` 提供了几条可选加速路径，依赖缺失时自动降级到 OpenCV，不影响功能：

- **raw 截图** —— `exec-out screencap` 直接拿 RGBA 原始数据，跳过 PNG 编解码（约 2~3 倍提速），再一步转灰度跳过 BGR 中间步骤。
- **Numba JIT** —— 并行加速 RGBA / BGR 灰度转换，以及 `TM_CCOEFF_NORMED` 模板匹配。
- **PyTurboJPEG** —— JPEG 解码提速 2~5 倍（DLL 缺失时优雅降级）。
- **多线程匹配** —— OpenCV 的 `matchTemplate` 会释放 GIL，界面可选择 1~8 个匹配线程实现真正并行。
- **模板缓存** —— 模板加载一次后缓存在内存，避免重复磁盘读取。

可通过 `get_acceleration_status()` 查询当前加速模块的可用状态，启动时会写入 image 日志。

## 常见问题

<details>
<summary><b>程序启动后一闪而过，没有任何界面？</b></summary>

控制台会被主动隐藏，启动失败时程序会弹出原生错误对话框。如果连弹窗都没有，请在命令行中执行 `python main.py` 查看完整报错——通常是依赖未装齐，运行 `bat\install.bat` 即可。
</details>

<details>
<summary><b>提示分辨率不符合要求？</b></summary>

模拟器分辨率必须为 720p（宽或高任意一个为 720，例如 `1280×720`）。请在模拟器设置中调整后重启模拟器再连接。
</details>

<details>
<summary><b>设备列表为空 / 连接失败？</b></summary>

确认模拟器已开启 ADB 调试，且 IP 端口填写正确（MuMu 常见为 `127.0.0.1:16384`，雷电常见为 `127.0.0.1:5555`）。可在菜单栏「程序 → 重启ADB并重启程序」重置 ADB 服务后再试。
</details>

<details>
<summary><b>识别不到图片 / 频繁停止？</b></summary>

- 确认游戏画面停留在场景对应的界面；
- 适当降低该场景的识别阈值（设备标签页内可调，按场景独立记忆）；
- 开启「设置 → 日志 → 启用日志记录」，在 `logs/image_*.log` 中查看每个模板的置信度，判断是阈值问题还是模板过时。
</details>

<details>
<summary><b>日志文件在哪里？</b></summary>

`logs/` 目录下按时间戳生成三类日志：`GUIlog_*.log`（界面与运行逻辑）、`adb_*.log`（ADB 命令）、`image_*.log`（识图结果与性能统计）。默认不记录，需在菜单栏开启。
</details>

<details>
<summary><b>任务结束后没有声音 / 没有通知？</b></summary>

提示音需在设置页勾选「启用提示音」并选择音效文件；系统通知需开启「通知」开关。手动点击「停止」结束任务时不会播放提示音。若系统通知不显示，请检查 Windows 的「通知和操作」设置是否允许该应用推送。
</details>
