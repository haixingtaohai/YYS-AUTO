核心模块

界面层与引擎层分离，各模块各司其职，构成完整的自动化引擎

■ main.py -- 启动入口
~101 行
V2.16 起 main.py 只负责启动：把项目根目录放进 sys.path、设置 Windows 进程标识（AppUserModelID）与任务栏图标、隐藏控制台，然后创建主窗口。启动失败会弹原生对话框提示——控制台此时已隐藏，没有这个提示用户只会看到程序"闪一下就没了"。界面逻辑全部搬到 ui/ 包。
启动引导 AppUserModelID 失败弹窗 V2.16 拆分
■ ui/ -- 界面层
~2757 行 / 8 个模块
V2.16 把原来 2700 多行的 main.py 按职责拆成 8 个模块：app.py 主窗口与菜单栏、device_tab.py 设备标签页、settings_tab.py 设置页、scene_runner.py 运行循环、dialogs.py 各类对话框、config_store.py 配置读写、ime.py 输入法控制、widgets.py 自定义控件。运行循环与对话框用 mixin 挂回主类，避免改动大量 self.* 引用。
AutoClickerUI DeviceTab SettingsTab SceneRunner DialogsMixin Menu 菜单栏 快捷键绑定 使用时长记录 JSON 配置
■ presets.py / paths.py
~102 / ~35 行
V2.16 新增的两个数据模块。presets.py 集中存放 14 个场景的预设（模板目录、点击坐标、识别阈值、是否统计挑战次数）；paths.py 统一推导所有路径常量。后者很关键：程序由 bat/run.bat 以 python ..\main.py 启动，工作目录不保证是项目根目录，用 __file__ 统一推导才能保证配置和模板目录永远找得到。
场景预设表 ROOT_DIR 路径常量 V2.16
■ image_recognizer.py
~450 行
OpenCV 模板匹配引擎。使用 TM_CCOEFF_NORMED 归一化交叉相关算法，配合 ADB 截图和点击模拟，实现高精度游戏界面识别。内置详细日志记录，将每次识别结果（图片名称、中心坐标、置信度）写入 logs 目录。
ImageRecognizer matchTemplate 模板缓存 阈值 0.90 日志记录 性能优化 (V2.10)
■ adb.py
~143 行
ADB 设备管理层与日志基础设施。负责模拟器通信、自动发现 platform-tools 目录、验证设备分辨率（强制 1280x720）。V2.6 引入 _FilterDisabled 过滤器类 + set_logging_enabled() 全局开关，日志默认关闭，用户可在菜单栏中启用。
ADBManager 设备发现 分辨率验证 logging
■ notification.py
~185 行
V2.9 新增系统通知模块。使用 winotify (Windows Toast API) 发送系统级通知，若未安装则自动回退到 PowerShell 托盘通知。支持完成/错误两种通知类型，可在设置中开关和测试。自动注册开始菜单快捷方式以确保通知来源名称正确显示。
Toast 通知 winotify PowerShell 回退 可开关
■ image_accelerator.py
~336 行
V2.10 新增图像识别加速模块。使用 Numba JIT 并行加速 RGBA/BGR 灰度转换与 TM_CCOEFF_NORMED 模板匹配，PyTurboJPEG 加速 JPEG 解码（快 2-5 倍），并支持 raw screencap 一步转灰度。未安装依赖时自动优雅降级到 OpenCV，通过 get_acceleration_status() 查询加速状态。
Numba JIT PyTurboJPEG raw screencap 优雅降级 并行加速
■ wav.py
~175 行
V2.15 拆分新增提示音设置模块。管理 wav/ 音效文件目录，支持导入音效、试听、配置任务结束提示音开关与播放，内置 QQ、Steam、iOS 信息/通知、言灵、骄阳长明等多款音效。
提示音 音效管理 试听 wav/ 目录 V2.15

// config.json - 持久化配置示例（每个设备标签页一条记录） { "last_tab": 1, // 上次停留的标签页（0 是设置页） "tabs": { "1": { "tab_name": "设备1", // 标签名称 "device": "emulator-5554", // 该标签使用的设备 "preset": "结界突破", // 当前场景预设 "target_count": "40", // 目标挑战次数 "threshold": "0.8", // 当前识别阈值 "match_workers": "4", // 模板匹配线程数 "preset_thresholds": { // 每个场景各自记住的阈值 "业原火": "0.8", "结界突破": "0.8" } } }, "window_geometry": "640x460+100+100", // 窗口位置与尺寸记忆 // ---- 全局设置（菜单栏 / 设置页）---- "link_enabled": false, // 司机-队员联动 "huijuan_mode": false, // 绘卷模式 "dj_jinsheng_stop": false, // 斗技段位晋升后结束程序 "close_jiacheng_enabled": false, // 任务完成后关闭御魂加成 "close_jiacheng_wait": 30, // 关闭加成前的等待秒数 "dinghao_wait": 30, // 被顶号后等待进入游戏的秒数 "ql_fangqi": true, // 契灵：放弃结契 "ql_zaici": false, // 契灵：再次结契 "sound_enabled": false, // 任务结束提示音 "sound_file": "", // 选中的音效文件名 "notify_enabled": true, // 系统通知 "logging_enabled": false, // 详细日志记录 // ---- 走神模式 ---- "zoushen_enabled": false, // 开关（默认关闭） "zoushen_trigger_min": 60, // 触发时间下限（秒） "zoushen_trigger_max": 180, // 触发时间上限（秒） "zoushen_duration_min": 5, // 持续时长下限（秒） "zoushen_duration_max": 15, // 持续时长上限（秒） "zoushen_whitelist": ["司机", "队员"], // 白名单场景不触发 // ---- ADB ---- "adb_ip": "127.0.0.1", "adb_port": "16384" }

配置文件由 ui/config_store.py 用一张声明式字段表读写，读写共用同一份字段定义。读取时会原样保留文件里所有键（包括版本升级后遗留的旧键），保存时整体写回，因此不会因为增减字段而丢失标签页配置。

快速开始

按照以下步骤快速部署和运行 YYS-AUTO

1
安装 Android 模拟器
安装 MuMu、雷电或其他支持 ADB 的 Android 模拟器。在模拟器设置中将分辨率调整为 1280x720（横屏），并开启 ADB 调试。
2
安装 Python 依赖
确保已安装 Python 3.8 或更高版本，然后运行 install.bat 或手动执行 pip install opencv-python。
3
连接 ADB 设备
在模拟器中查看 ADB 端口（通常为 5555），在 YYS-AUTO 中输入对应的 IP 和端口连接设备。程序会自动检测设备分辨率是否符合要求。
4
选择场景并启动
在选项卡中选择需要的游戏场景预设（如业原火、魂土等），设置挑战次数和其他参数，点击启动即可开始自动化运行。
5
等待完成
程序会在后台自动运行。任务完成后播放音效通知。可随时通过界面停止或调整参数。所有设置自动保存，下次启动无需重新配置。
